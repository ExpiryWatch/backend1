# ExpiryWatch — Backend 1

Серверная часть веб-приложения ExpiryWatch для учёта домашних запасов и контроля сроков годности продуктов.

Backend разработан на FastAPI с использованием SQLAlchemy и SQLite.

## Возможности

- Добавление, просмотр, изменение и удаление продуктов (CRUD).
- Автоматическое определение статуса срока годности.
- Поиск, фильтрация и сортировка продуктов.
- Получение категорий и мест хранения.
- Пагинация списка продуктов.
- Проверка входных данных и обработка HTTP-ошибок.
- Интерактивная документация Swagger.

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/ExpiryWatch/backend1.git
cd backend1
```

### 2. Создание виртуального окружения

```bash
python3 -m venv .venv
```

Активация окружения на macOS/Linux:

```bash
source .venv/bin/activate
```

### 3. Установка зависимостей

```bash
python -m pip install -r requirements.txt
```

### 4. Инициализация базы данных

```bash
python -m app.init_db
```

При первоначальной настройке для добавления демонстрационных данных можно выполнить:

```bash
python -m app.seed
```

### 5. Запуск сервера

```bash
python -m uvicorn app.main:app --reload
```

После запуска сервер доступен по адресу:

http://127.0.0.1:8000

Документация Swagger UI:

http://127.0.0.1:8000/docs


## API Endpoints

### Управление продуктами

| Метод | Endpoint | Описание |
|---|---|---|
| GET | `/inventory/` | Получить список продуктов |
| GET | `/inventory/{item_id}` | Получить продукт по ID |
| POST | `/inventory/` | Добавить новый продукт |
| PUT | `/inventory/{item_id}` | Обновить существующий продукт |
| PATCH | `/inventory/{item_id}` | Частично обновить продукт |
| DELETE | `/inventory/{item_id}` | Удалить продукт |


### Обновление продуктов

Приложение поддерживает два способа обновления продуктов.

**PUT** — полное обновление продукта. Требует передачи всех изменяемых полей. Если обязательные поля запроса отсутствуют, возвращается HTTP 422.

Пример:

```json
{
  "name": "Молоко",
  "quantity": 2,
  "unit": "л",
  "category_id": 1,
  "storage_location_id": 1,
  "purchase_date": "2026-11-13",
  "expiry_date": "2026-11-25",
  "comment": null
}
```

**PATCH** — частичное обновление продукта. Изменяет только переданные поля, сохраняя остальные значения.

Пример:

```json
{
  "quantity": 5
}
```

При обновлении выполняется проверка входных данных, категорий и мест хранения. Некорректные значения отклоняются с HTTP 422.

Приложение также позволяет учитывать просроченные продукты: они сохраняются со статусом `expired`.


### Категории и места хранения

| Метод | Endpoint | Описание |
|---|---|---|
| GET | `/categories/` | Получить категории и количество продуктов в каждой |
| GET | `/storage-locations/` | Получить места хранения и количество продуктов в каждом |

## Поиск, фильтрация и сортировка

Метод `GET /inventory/` поддерживает следующие параметры:

| Параметр | Описание |
|---|---|
| `q` | Поиск по названию продукта |
| `category_id` | Фильтрация по категории |
| `storage_location_id` | Фильтрация по месту хранения |
| `status` | Фильтрация по статусу срока годности |
| `sort` | Поле сортировки: `name` или `expiry` |
| `order` | Направление сортировки: `asc` или `desc` |
| `limit` | Максимальное количество продуктов в ответе |
| `offset` | Количество пропускаемых записей |

### Примеры запросов

Поиск молока:

```http
GET /inventory/?q=молоко
```

Получение просроченных продуктов:

```http
GET /inventory/?status=expired
```

Сортировка по сроку годности:

```http
GET /inventory/?sort=expiry&order=asc
```

Получение трёх продуктов с пропуском первых трёх:

```http
GET /inventory/?limit=3&offset=3
```

Параметры можно комбинировать между собой.


## Статусы срока годности

Приложение автоматически определяет статус каждого продукта на основе даты окончания срока годности.

| Статус | Описание |
|---|---|
| `fresh` | Продукт годен |
| `expiring_soon` | Срок годности скоро истекает |
| `expired` | Продукт просрочен |
| `no_date` | Срок годности не указан |

Дополнительно API возвращает:

- `status_label` — название статуса на русском языке.
- `days_left` — количество дней до истечения срока годности.

Для просроченных продуктов `days_left` отрицательное.

Если дата окончания срока годности не указана, `days_left` равен `null`.

## HTTP-коды и обработка ошибок

Backend использует стандартные HTTP-коды:

| Код | Описание |
|---|---|
| `200 OK` | Успешное получение, обновление или удаление |
| `201 Created` | Продукт успешно создан |
| `404 Not Found` | Продукт с указанным ID не найден |
| `422 Unprocessable Content` | Некорректные входные данные |

Ошибки возвращаются в едином JSON-формате.

Пример:

```json
{
  "detail": "Категория с ID 999999 не найдена"
}
```

При создании и обновлении продуктов проверяется:

- Название продукта не должно быть пустым.
- Название не должно состоять только из пробелов.
- Количество продукта должно быть больше нуля.
- Указанная категория должна существовать в базе данных.
- Указанное место хранения должно существовать в базе данных.

При некорректных данных запрос отклоняется с соответствующим HTTP-кодом.

```text
app/
├── main.py
├── database.py
├── init_db.py

├── queries.py
├── models/

│   ├── category.py

│   ├── categories.py
│   └── storage_locations.py
└── schemas/

```

### Назначение основных файлов

- `main.py` — создание приложения FastAPI и подключение маршрутов.
- `database.py` — подключение к SQLite и управление сессиями SQLAlchemy.
- `init_db.py` — создание таблиц базы данных.
- `seed.py` — добавление демонстрационных данных.
- `queries.py` — запросы к базе данных, фильтрация и сортировка.
- `models/` — модели таблиц базы данных.
- `routers/` — обработчики HTTP-запросов.
- `schemas/` — схемы Pydantic для проверки данных и формирования ответов.

## База данных

Приложение использует SQLite через SQLAlchemy.

Данные хранятся в локальном файле `pantry.db` и сохраняются между перезапусками сервера.

Файл базы данных исключён из Git. Для создания локальной базы используется команда:

```bash
python -m app.init_db
```

Для добавления демонстрационных данных:

```bash
python -m app.seed
```
