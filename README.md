# ExpiryWatch — локальный учебный релиз

Общее приложение «Запасы»: главный экран Frontend-1, формы frontend2,
FastAPI backend1, бизнес-правила backend2 и SQLAlchemy/SQLite из слоя БД команды.
Фронтенд обращается к API; localStorage и демонстрационные HTML-карточки не используются.

## Запуск на Windows

Python 3.11+ (проверено на Python 3.15; тесты используют `unittest.enterContext`). Команды PowerShell из корня этого репозитория:

```powershell
cd D:\zapasi\backend1
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m app.init_db
.\.venv\Scripts\python.exe -m app.seed
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Если окружение уже создано, `python -m venv .venv` пропустить.
Для другого расположения клона заменить только путь в `cd`.

## Запуск на macOS/Linux

Если репозиторий ещё не клонирован:

```bash
git clone --branch feature/business-rules-integration https://github.com/ExpiryWatch/backend1.git
cd backend1
```

В уже существующем клоне перейти в его корень и переключиться на
`feature/business-rules-integration`. Затем выполнить:

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements-dev.txt
./.venv/bin/python -m app.init_db
./.venv/bin/python -m app.seed
./.venv/bin/python -m unittest discover -s tests -v
./.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Нужен установленный Python 3.11 или новее; если `.venv` уже создано, первую команду
пропустить. Окружение создаётся на каждом компьютере отдельно, копировать Windows `.venv` на Mac нельзя.
Активация окружения не обязательна: команды выше явно используют его Python.

## Адреса и данные

- Приложение: **http://127.0.0.1:8000/ui/**.
- Swagger: http://127.0.0.1:8000/docs.
- Проверка сервера: http://127.0.0.1:8000/ (JSON).
- Остановка сервера: Ctrl+C. Повторный запуск — последняя команда.

`app.init_db` создаёт недостающие таблицы. `app.seed` заполняет справочники и добавляет
шесть демонстрационных позиций в пустую БД; повторный запуск не дублирует их.
Для пустого списка с готовыми справочниками можно удалить демонстрационные позиции через интерфейс.
Для расширенных данных использовать `python -m app.seed --extended` через тот же интерпретатор.

Данные сохраняются в `pantry.db`, файл исключён из Git. Запускать из корня репозитория,
чтобы относительный путь БД оставался одинаковым. База `backend2/demo.sqlite3` не переносится
и не изменяется. Перед заменой существующей `pantry.db` сохраните её копию.
Скрипт `app.migrate_expiry_constraint` из исходной ветки для запуска интеграции не нужен.
Команда `app.seed --reset` удаляет данные — для обычного запуска её не использовать.

## Возможности

- Создание, просмотр, редактирование и удаление позиций через единый API.
- Поиск по кириллице без учёта регистра, «ё» = «е»; совместные фильтры по статусу, категории и месту.
- Сортировка по названию и сроку в обоих направлениях; позиции без срока всегда в конце.
- Общая статистика через `/stats/`, справочники с реальными ID из БД.
- Четыре статуса и дни до срока рассчитываются при чтении; открытая страница обновляется раз в минуту и при возвращении фокуса.
- Русские сообщения об ошибках; неверный ввод сохраняет форму открытой и не меняет другие позиции.
- Индикатор загрузки и кнопка повторной попытки при ошибке получения данных.
- Поля блокируются во время сохранения; PATCH формы отправляет только изменённые значения, включая `null` при очистке необязательного поля.
- Адаптация главного экрана и форм для ширины 360px.

## Бизнес-правила

Обязательны непустое название и положительное количество. Количество — JSON-число,
конечное, с точностью до двух знаков и максимумом `99999999.99` по формату БД.
ТЗ не задаёт максимум и точность количества: это технические ограничения текущей
ветки для модели `NUMERIC(10,2)`, предотвращающие округление сохранённого значения.
Фронтенд и API проверяют одинаковые пределы; их изменение требует согласования
хранения и интерфейса, а не только правки одного валидатора.

Дата покупки необязательна. Порядок дат не проверяется ни в API, ни в форме:
срок может быть раньше покупки. Существование календарной даты и формат
`YYYY-MM-DD` по-прежнему проверяются. Статус зависит только от срока годности
и текущей даты. Неизвестные поля отклоняются, статусы менять вручную нельзя.

В переданном ТЗ есть запрет срока раньше покупки. Текущая ветка следует запрошенному
в ревью правилу команды, разрешающему такой порядок; расхождение с ТЗ нужно
согласовать перед сдачей.

| Осталось дней | Статус |
|---|---|
| Больше 3 | `fresh` — Годен |
| От 0 до 3 | `expiring_soon` — Скоро истекает |
| Меньше 0 | `expired` — Просрочено |
| Даты нет | `no_date` — Срок не указан |

«Сегодня» — локальная дата компьютера с сервером. Для защиты от параллельных изменений
SQLite получает блокировку записи до чтения текущей позиции.
Схема существующей БД не меняется. Если в старой БД осталось ограничение порядка дат,
оно может вернуть конфликт 409; это не проверка Pydantic. Перед изменением такой БД
нужно отдельно согласовать миграцию и сохранить резервную копию.

## API и структура

Контракт: [docs/API_CONTRACT.md](docs/API_CONTRACT.md).
Правила командной работы: [docs/GIT_FLOW.md](docs/GIT_FLOW.md).

| Методы | Путь |
|---|---|
| GET, POST | `/inventory/` |
| GET, PUT, PATCH, DELETE | `/inventory/{id}` |
| GET | `/categories/`, `/storage-locations/`, `/stats/` |

`app/schemas/inventory.py` — общая валидация; `app/models/stock_item.py` — существующий расчёт сроков;
`app/queries.py` — единая реализация поиска, фильтров, сортировки и статистики;
`app/routers/` — API; `frontend/` — объединённый интерфейс; `tests/` — проверки интеграции.

## Проверки

13 автотестов на временной файловой БД: неверный ввод через POST/PUT/PATCH,
сохранность данных, перезапуск соединения, CRUD, границы сроков и смена дня,
справочники, поиск/фильтры/сортировка, статистика, конкурирующие PATCH,
проверка времени API на 1000 позициях и доступность фронтенда, независимые даты,
границы количества и откат транзакции при конфликте 409.

Дополнительный браузерный сценарий на изолированной временной БД:

```powershell
.\.venv\Scripts\python.exe -m pip install playwright==1.65.2
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -m tests.browser_smoke
```

Для macOS/Linux:

```bash
./.venv/bin/python -m pip install playwright==1.65.2
./.venv/bin/python -m playwright install chromium
./.venv/bin/python -m tests.browser_smoke
```

На Linux для системных библиотек Chromium может понадобиться
`./.venv/bin/python -m playwright install --with-deps chromium`.

Проверяет создание, ошибки формы и API, фильтры, редактирование, перезагрузку,
отмену/подтверждение удаления, безопасный вывод пользовательского текста и ширину 360px.
Также проверяет повторную загрузку после ошибки, автофокус, блокировку полей при
сохранении, состав PATCH, очистку комментария и сохранность внешних изменений
полей, которые пользователь не редактировал.
Тесты не используют пользовательскую `pantry.db`.
